# v0.18.0 — EV charging history

**New.** Home Assistant kept no long-term record of EV charging: `EV Power` had no state class, so the recorder threw it away after ~10 days, and there was no energy counter at all. The data was never lost, though. The go-e keeps its own lifetime meter, Wattsmith's history DB has logged EV energy every 15 minutes since July, and the removed go-e integration left hourly meter statistics behind.

**What changed**
- New **Wattsmith EV EV Energy** sensor (`sensor.wattsmith_ev_ev_energy`): the charger's lifetime meter (`eto`), kWh, `total_increasing`. Add it to the Energy dashboard under *Individual devices*.
- **Wattsmith EV EV Power** now has `state_class: measurement`, so HA keeps hourly mean/min/max for good.
- New action **`wattsmith.backfill_ev_energy`** writes the EV Energy history from before the sensor existed into its long-term statistics:
  - With `meter_statistic_id` (e.g. `sensor.goe_318468_eto` from the old go-e integration) the meter's own hourly readings are used as they are.
  - From there to the sensor's first hour, the meter delta is spread over the hours in proportion to the 15-min `ev_wh` log. So the totals are the meter's and only the hour-by-hour shape comes from the log. The response's `scale` says how closely the log matches the meter (1.0 = perfect).
  - The sensor's own rows are re-summed so the dashboard sees one continuous counter with no seam.
  - Dry run by default. Running it again does nothing.

**How to use it**
1. Update, restart, and wait until **EV Energy** has been recording for a full hour.
2. Developer Tools → Actions → `wattsmith.backfill_ev_energy` with `meter_statistic_id: sensor.goe_318468_eto`, dry run on, *Return response*. Check `monthly_kwh` and `scale`.
3. Run it again with `dry_run: false`.
4. Settings → Dashboards → Energy → *Individual devices* → add **Wattsmith EV EV Energy**.
