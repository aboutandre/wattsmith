# v0.18.0 — Wattsmith now records Solcast's P10 and P90

The history DB kept only Solcast's central (P50) forecast. The pessimistic (P10) and optimistic (P90) figures that the dashboard's "Solcast Tomorrow" card shows were live values only: Home Assistant's own recorder keeps no P10/P90 and purges after about 10 days, so nobody could ever check whether that range is honest. From this version Wattsmith writes both down.

**Two new records**

- **P10 and P90 on every 15-minute bucket.** The `bucket` table gets `pv_forecast_p10_wh` and `pv_forecast_p90_wh` next to `pv_forecast_wh`, for the same slot. Compare them with `pv_wh` to see how often the sun lands below P10 or above P90.
- **A snapshot of the day-ahead forecast (new table `pv_forecast_snapshot`).** At **13:15**, just after tomorrow's prices publish and the planner first sees tomorrow, and again at **21:00**, the last plan before the overnight cheap window, Wattsmith copies Solcast's whole forecast: central, P10 and P90 for every 30-minute period of tomorrow, plus the rest of today. Each row carries its lead time (`lead_h`), so day-ahead and same-day forecasts for the same hour can be told apart. About 55 to 60 rows per snapshot: 48 for tomorrow plus what is left of today.

Until now the history held only a forecast read a few hours ahead of each bucket, which flatters Solcast. Measured that way on 86 days it was 6.5 % off per day. The day-ahead forecast is the one the planner actually buys energy on; on the 9 days that could be checked it was about 10 % off. That is too few days to trust, and it was never recorded. Late October is the target for a first accuracy report.

**Reading it back.** `wattsmith.query_history` accepts `table: pv_forecast_snapshot`. The date range applies to the forecast's *target* period, so a window covering one day returns every forecast made for that day. Query the `bucket` table for the same window to get the actuals. The service's table list in the UI now also shows `battery_health` and `calibration_event`, which the service already accepted.

**What changes for you**

- Nothing visible: no new entities, and the planner is untouched.
- Your existing history DB upgrades in place on the first start (columns and a table are added, no rows are rewritten). Old buckets keep empty P10/P90 columns; recording starts now and nothing earlier can be recovered.
- If Home Assistant was restarted or reloaded while a snapshot was due, it is taken about two minutes after startup instead of being skipped.
- The snapshot times are `HISTORY_FORECAST_SNAPSHOT_TIMES` in `settings.py`. They are not in the options UI.
- If `Solcast forecast snapshot: no forecast periods available` appears in the log, the Solcast sensor had no forecast at that moment (for example after a failed Solcast update). That one snapshot is skipped; the next one is unaffected.

**Please check after updating:** a few minutes after the restart, `wattsmith.query_history` with `table: pv_forecast_snapshot` for the coming day should return rows with `p10_wh` and `p90_wh` filled in.
